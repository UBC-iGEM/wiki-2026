# <a id="3fcd65dd82be80e9bed1f5180f50e1b2" />Introduction

<a id="3fcd65dd82be80f8a53efbbd4bc7f826" />FAST requires promoters that respond to antibiotic exposure and can activate a measurable reporter. Antibiotic treatment can change the expression of thousands of genes, so identifying an antibiotic-responsive promoter involves integrating many factors. PRISM corroborates *Escherichia Coli* expression data with regulatory interactions, promoter annotations, and sequencing information.

<a id="3fdd65dd82be80bb9ef0facec0c9b7e7" />Our contribution is the integration, interpretation and review workflow. The expression model, source measurements, and regulatory annotations come from the cited methods and resources. PRISM makes their relationships inspectable and produces a reproducible selection proposal.

<a id="3fdd65dd82be80dabb7ed635d244a680" />PRISM produces differential-expression evidence, regulatory context, promoter and transcription unit mappings, candidate assessments, a proposed first-pass screening panel, and a searchable database.

# <a id="3fcd65dd82be80d0a284d41cc22f0417" />Pipeline

<a id="3fdd65dd82be8038a5dce6a7e21ef457" />PRISM combines RNA-seq data with regulatory and genomic annotations. The pipeline connects pieces of evidence and filters to produce promoter candidates for experimental screening. Each output retains a link to the source data which allows for review and reproducibility.

<a id="3fdd65dd82be806f937ad5dfdad81134" />These inputs were chosen to keep the analysis consistent internally as PRISM favours traceability within one dataset and strain. Dataset GSE220559 provides antibiotic test conditions to reference. Due to the lack of available data directly applicable to our project, ceftazidime and kanamycin serve as beta-lactam and aminoglycoside proxies respectively. ## <a id="3fdd65dd82be8059a61dfb30dc23998a" />Input Validation

<a id="3fdd65dd82be809bb08ff9ee02edfbb4" />Data validation is one of the important preprocessing steps of the datapipeline. Checks are implemented at multiple steps. Valid inputs are checked through whether sample identifiers and count matrix columns agree. Shared water controls are compressed to one set use for the final model.

## <a id="3fdd65dd82be80cb9973c6dc16464de5" />Design Choices

### <a id="3fdd65dd82be8037b065eec1d2cf06f4" />One expression model

<a id="3fdd65dd82be809a920bd2b3f81095b8" />All conditions were fitted in one model so that they shared the same normalization, gene filter, and statistical framework. The count model follows DESeq2, implemented using PyDESeq2. The model uses raw integer counts and estimates dispersion using information across genes.

### <a id="3fdd65dd82be80cf80fffc992f812242" />Antibiotic roles labelled

<a id="3fdd65dd82be808e9880ed27aeedd184" />Each antibiotic was assigned a defined role: discovery proxy, robustness comparison, or cross-reactivity challenge. This prevents PRISM from treating every drug as equivalent to a wetlab target.

### <a id="3fdd65dd82be80498011ea3c11ed529c" />Candidate seeding

<a id="3fdd65dd82be80ee973fcdba95bf6afb" />Candidate genes were required to have an adjusted p-value below 0.05 and a log2 fold change greater than 2. These are screening thresholds chosen to prioritize strong, statistically supported induction; they are not universal biological boundaries.

<a id="3fdd65dd82be80988308c0538df20257" />Benjamin–Hochberg adjustment is applied separately within each drug-versus-control contrast. The combination of selected genes across contrasts cannot necessarily demonstrate to have a five percent false-discovery rate. Direct drug-versus-drug assessment additionally adjusts across the ten pairwise comparisons before candidate selection.

### <a id="3fdd65dd82be80489d4cf7517e049cc1" />**Full measured background**

<a id="3fdd65dd82be805eb3e1dd82179160ad" />Regulon enrichment used all eligible measured and mapped genes as its background. Restricting the background to selected candidates would exaggerate regulatory enrichment.

### <a id="3fdd65dd82be808695bfce847b20a8ba" />**Evidence-preserving graph**

<a id="3fdd65dd82be802595ebd647646fd923" />PRISM keeps direct curated regulation separate from promoter, transcription-unit, and gene membership. Missing links remain visible rather than being filled with unsupported assumptions.

### <a id="3fdd65dd82be80ff81a7ed6647394128" />**Balanced screening panel**

<a id="3fdd65dd82be80459f1ed868cf9e468c" />The proposed panel contains six candidates per antibiotic class and limits repeated promoters or connected transcription-unit groups. It uses a deterministic greedy rule: supporting comparisons, threshold-screen stability, promoter annotation confidence, regulator reuse, direct comparisons, counterpart effects, and shrunken induction, with identifiers breaking remaining ties. This is a screening heuristic; information gain and biological optimality have not been established.

### <a id="3fdd65dd82be8082bdbad7cdbe4ba2a5" />**Relational evidence database**

<a id="3fdd65dd82be80858deed6c18bf6bf8a" />SQLite was chosen because PRISM contains many linked record types: genes, treatments, comparisons, promoters, regulators, candidates, assessments, and source assets. Stable relationships allow every candidate decision to be traced back to its raw data and evidence.

### <a id="3fdd65dd82be80dd9aabf4d02c3052d3" />**Separate review history**

<a id="3fdd65dd82be806f93b0f6c3de10ea17" />Manual decisions are stored separately from imported measurements. Reviewers can approve, exclude, or annotate candidates without altering the underlying scientific evidence.

## <a id="3fdd65dd82be8077bb0ff8c955ac0091" />**Expression Data to Promoter Candidates**

1. <a id="3fdd65dd82be80019595f65839172287" />**Verify source data:** PRISM checks required datasets, reference versions, and source-file hashes before analysis.
2. <a id="3fdd65dd82be8020bdd2d344149da9ea" />**Fit the expression model:** A joint differential-expression model compares each antibiotic condition against the shared water control.
3. <a id="3fdd65dd82be80e5abacdec5ed25b720" />**Identify responsive genes:** Genes passing the expression, effect-size, and adjusted p-value thresholds become candidate seeds.
4. <a id="3fdd65dd82be80788547f1d1904c2ca5" />**Add curated regulatory context:** Candidate responses are overlaid onto curated relationships among regulators, promoters, transcription units, and genes.
5. <a id="3fdd65dd82be807eb25eebd729c97d09" />**Map candidate promoters:** PRISM identifies promoter records associated with each candidate gene and checks available coordinates against the MG1655 genome.
6. <a id="3fdd65dd82be802d83defb2ba0b212e6" />**Assess candidate quality:** Candidates are evaluated for replicate consistency, threshold stability, cross-reactivity, operon support, and sequence availability.
7. <a id="3fdd65dd82be8080a5fcdff53ff923c8" />**Select the screening panel:** A balanced first-pass panel is created while limiting repeated promoters and connected transcription-unit groups.
8. <a id="3fdd65dd82be802bb601ef97999d42b0" />**Build the evidence database:** Expression results, regulatory paths, promoter records, assessments, and provenance are imported into a searchable SQLite database.

### <a id="3fdd65dd82be8041b6dec8c415f7bc9a" />**Tested database iteration: evidence identity and context**

<a id="3fdd65dd82be80b88b32e29aaf190df1" />During review, searching the source locus `b0113` did not find the `pdhR` candidate, even though its expression evidence used that locus. A synthetic insertion also showed that a DE row could name one run while referencing another run's contrast. The existing database contained no such cross-run mismatch.

<a id="3fdd65dd82be80d48fc7c663ab08c2b9" />We added source-linked identifier associations and composite run–contrast foreign keys. Regression tests now verify that locus searches retrieve the correct candidate, that distinct source loci remain distinct, that ambiguous identifiers are not silently resolved, and that inconsistent run links are rejected. Additional tests check cited sample context, preservation of unknown values, and retention of superseded evidence snapshots. These results demonstrate a completed software engineering iteration; they do not validate promoter activity.

<a id="3fdd65dd82be80f8ae7df5ae6cb1215e" />The next iteration will replace proxy-only evidence with reporter measurements under amoxicillin, cephalexin, gentamicin, and tobramycin. Those measurements can then be linked to existing PRISM candidate and promoter records and used to revise the ranking.

<a id="3fdd65dd82be80d4a77bd6bb28d16c49" />The primary benchmark contains 18 unique RNA-seq samples: three biological replicates for each condition, including shared water controls. Five drug-versus-control comparisons and ten direct drug-versus-drug comparisons were fitted in one PyDESeq2 model using condition as the design variable.

<a id="3fdd65dd82be80b8a262c581e1a28947" />Genes required at least ten counts in three samples. A total of 4,176 genes passed this common expression filter. Candidate seeds required an adjusted p-value below 0.05 and an log₂ fold change above 2.

# <a id="3fcd65dd82be8077860eff7d8dfdce54" />Database

<a id="3fdd65dd82be80dab302eeeeecbc281a" />PRISM stores datasets, genes, antibiotics, contrasts, differential-expression results, regulatory interactions, promoters, transcription units, candidate evidence, proposed panels, assessment records, replicate summaries, and fragment-review information in a relational SQLite database.

<a id="3fdd65dd82be80e9b864db96ea08d137" />The unit of a candidate is a gene-level evidence record. A separate many-to-many mapping associates candidates with possible promoters. The panel records the promoter proposed for testing. Source loci remain attached to individual expression results. Identifier associations retain their source row, reference release, and mapping basis, including cases where a symbol has more than one source locus.

<a id="3fdd65dd82be80269b48dd160efcc80f" />SQLite supports the current local, single-study workflow without a server. Foreign keys enforce record relationships, including matching run identities for contrasts and measurements. The schema also retains unknown context as null values. It is a portable scientific snapshot, not a multi-strain database or a laboratory information-management system.

## <a id="3fdd65dd82be806bb5bae0a23947a7f4" />**Explorer features**

- <a id="3fdd65dd82be806f911cfc8ba7d5093e" />Search by gene symbol, source locus, or candidate name
- <a id="3fdd65dd82be80c5b8e4ded04d7ff675" />Filter by antibiotic class and support tier
- <a id="3fdd65dd82be8052a027ee5812f309d2" />Filter by adjusted p-value and log₂ fold change
- <a id="3fdd65dd82be80f69847e96e338fa975" />Inspect promoter and transcription-unit mappings
- <a id="3fdd65dd82be8004aa8ddd798ccb7168" />Switch among regulators and inspect reference records
- <a id="3fdd65dd82be80c4acc2ef210c030478" />Review measured responses and statistical evidence
- <a id="3fdd65dd82be80989471cf0d6636c90a" />Examine replicate stability and cross-reactivity
- <a id="3fdd65dd82be80f29557d043517b4c2e" />Inspect cited source-study growth and exposure conditions
- <a id="3fdd65dd82be805780ffdb630ac4fa97" />Inspect promoter sequences and proposed fragments

<a id="3fdd65dd82be80bb88c9d52096bf6ebc" />The explorer is read only. Candidate and promoter reviews are recorded through the CLI or Python API. These reviews are attributable human decisions, not experimental measurements. A review status such as `validated` must be interpreted with its reason and supporting source; it does not automatically establish reporter validation.
